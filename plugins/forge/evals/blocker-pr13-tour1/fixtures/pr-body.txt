PR #13: feat(qc): arrêter la fusion par l'agent quand une règle never-weaken s'applique

## Résumé

Un projet peut déclarer, par la clé `never-weaken` de `docs/agents/usine.md`, des changements qu'aucun agent ne fusionne, même sur ACCEPT : un humain le fait, comme pour un chemin protégé. Une entrée est `<chemin> | <type> [| <paramètre>]`, le chemin étant un fichier ou un dossier (fini par `/`). Trois types fermés, décidés sur le diff seul :

- `removed-line` : une ligne retirée sous le chemin, un fichier supprimé ou sorti du chemin.
- `raised-number | <regex à un groupe>` : un nombre monte (lignes retirées et ajoutées d'un fichier appariées dans l'ordre).
- `lowered-rank | <champ> | <rang> > <rang> ...` : un rang baisse, le meilleur d'abord.

Pourquoi : élargir ce qu'un agent fusionne seul est une décision de gouvernance ; ce ticket ne fait que retirer des droits à l'agent (tri de `forge:staff-engineer`, décision de l'humain sur #5, `delegated-path` parti dans #8).

- `plugins/forge/scripts/never_weaken.py` (bibliothèque standard) lit un diff et rend une ligne par entrée (`APPLIES`, `NONE`, `INVALID`) et un code de sortie (0, 1, 2). Il réutilise `split_value` de `hooks/usine.py` (#11), ne lance aucune commande du projet (un test le garde).
- `forge:qc-gate` : sonde 10, le script sur le diff de la PR.
- `forge:qc-conf` : nomme les entrées qui s'appliquent dans la ligne `GATES` (`never-weaken : ...`), sans REJECT.
- `/forge:qc` : une entrée qui s'applique pose `needs-your-attention`, écrit la raison dans `Attention`, et ne fusionne pas, même sur ACCEPT.
- Gabarit `usine.md`, `README.md`, `docs/installation.md`, schéma du README (consigne de l'humain sur #5).

## Décisions que la spec ne fixait pas

- **Les entrées sont lues sur la base**, pas sur la tête (`git show origin/<base>:docs/agents/usine.md` passé à `--usine`) : sinon une PR retirerait la règle qui la juge. En plus, une PR qui retire ou modifie une ligne `never-weaken` de `docs/agents/usine.md` s'applique elle-même (dernière ligne de la sortie du script). Limite : une règle ajoutée par une PR ne protège qu'à partir de sa fusion.
- **Fail closed** : entrée à qui il manque une partie, type inconnu, paramètre absent ou mal formé : `INVALID`, code 2, jamais complétée ni lue comme « aucune ». Une valeur illisible ou hors échelle qui change s'applique (`raised-number`, `lowered-rank`). Sonde `FAIL` ou `NOT RUN` : `/forge:qc` arrête la fusion aussi.
- **Chemin** : un dossier se termine par `/`, sinon fichier exact (pas de préfixe brut comme `protected-path`).
- **Appariement** : lignes retirées et ajoutées appariées dans l'ordre par fichier ; une ligne ajoutée sans vis-à-vis (champ créé) ou retirée sans vis-à-vis (champ supprimé) n'est pas un « relevé » ou un « abaissé » ; supprimer un fichier ou une ligne se couvre par `removed-line`.
- **Une passe** : `/forge:qc` ne revoit plus en une passe (sans `forge:qc-gate`) une PR dont le diff touche le chemin d'une entrée, y compris du Markdown : la sonde ne tourne que dans `forge:qc-gate`.
- Le verdict reste ACCEPT (choix du coder, le ticket ne le dit pas) : la PR n'est pas rejetée, la décision de la fusionner revient à un humain.
- Ce dépôt n'a pas encore d'entrée `never-weaken` dans son propre `docs/agents/usine.md` : le ticket ne la demande pas.
- `CHANGELOG.md` et `version` : non touchés, ils s'ouvrent à la publication (`docs/contribuer.md`).
